# Chat KB Sync · AI 聊天知识库

一个面向本地 RAGFlow 的 Agent Skill 和同步脚本。把聊天里的问题、排查步骤与结果整理成可检索的笔记。**先补历史，然后只重建变化了的总结。原聊天不改动。**

| 环节 | 处理方式 |
| --- | --- |
| 本地知识库 | 从 RAGFlow 官方 Docker 部署起步；单建私有聊天库，不混入工作资料 |
| 对话来源 | Codex 本机会话、DeepSeek Harness v4 会话、其他 AI 的统一 JSON 导出 |
| 分类与拆题 | 机器人 → 水利会拆开；同题续聊更新原笔记；难判的先放本地待分类。新库可选同题不新增 RAGFlow 文档条目，只更新检索内容 |
| 新旧聊天 | 显式开启来源自动发现后能加入新聊天；修改时间用于静默检查和记录，正文哈希判断是否有内容变化，不漏掉同修改时间的编辑 |
| 日常同步 | 手动验收后可按本地时间定时运行；可选就绪检查和经授权的本机启动器；失败保留本机草稿，下次续跑 |
| 保密 | 默认完全不使用模型。脚本只访问显式配置的本机 RAGFlow；摘要属于抽取稿，不是模型改写 |

## 从哪里开始

1. 把 [chat-kb-sync](chat-kb-sync/) 放进 Agent 的技能目录，或请 Agent 读取 [SKILL.md](chat-kb-sync/SKILL.md)。这不会自动读取聊天。也可以只使用脚本。
2. 按 [部署与验收](chat-kb-sync/references/ragflow.md) 本机部署或复用 RAGFlow，按 [配置与运行](chat-kb-sync/references/usage.md) 先用两段**虚构**聊天验证分类、改版和检索。
3. 只配置有权处理的来源。单独运行 `scan`，先在本机审阅 Markdown；确认后才运行 `publish`。同意自动发布后才把 `sync` 交给定时工具。

仅运行虚构样例的检查命令（在仓库根目录执行）：`python -m unittest discover -s tests -v`。这不连接模型或真实知识库。另有 [本机隔离测试](chat-kb-sync/references/ragflow.md#5-同题原位更新检索可选)，只创建临时虚构资料集并在验收后清理。

**请别把本地配置、历史导出、生成笔记、批准清单、日志或密钥提交到 Git。** 公开的是流程和程序，不是聊天。客户资料与个人聊天分开；金融、凭据、个人信息等只能按你的保密规则处理，少量匹配规则不能代替审阅。

## 兼容性与边界

Python 3.10+；DSH v4 压缩聊天另需 `zstandard`。Codex 和 DSH 适配器覆盖已知的本地持久化格式，不代表能读取各自账号的所有云聊天、已删除聊天、附件原文或旧格式。其他软件使用批准过的导出转换，不需要修改同步核心。

这是 **v0.2 预览**。同一文档原位更新仅作用于全文检索，完整最新版在本机 Markdown；RAGFlow 的原件下载仍是首次导入的文件。旧库默认保留原更新方式，不自动迁移或删除历史版。启动恢复需指定自己的受信启动器，不会安装 Docker 或唤醒关机电脑。要做模型语义改写，参见 [可选编辑流程](chat-kb-sync/references/editorial.md)，默认同步不发送给云模型，也不会将笔记绑定到云聊天。
