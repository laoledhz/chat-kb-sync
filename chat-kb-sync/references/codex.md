# Codex 本机会话适配

这个适配器用于**经过授权的本机记录**；不是 Codex 全账号、全部设备或 ChatGPT 网页端的聊天导出器。它不会启动 Codex、登录账号、调用 MCP、读取认证文件或连接网络。

## 首次配置

1. 确认本机 Codex 主目录（常见为用户的 `.codex`；如果已有 `CODEX_HOME`，以实际安装为准）。在同步配置中显式填入这个本机绝对路径；不要把用户主目录或整个磁盘设为根目录。只查看该目录下的 `sessions`、`archived_sessions`。
2. 选择明确的归档范围：
   - **UUID 清单**：在 Codex 应用或经授权的本机会话索引里核对归属，只填写本账号、本人创建、同意归档的会话 UUID。每次增加范围时由用户核对新的 UUID。
   - **本账号连续归档**：仅当用户同意自动归档该本机账号的未来新聊天，并已从一条确认属于本人的记录或可信本机资料核实两个创建者字段时，设置 `scope: "verified-codex-owner"`，配置 `owner_account` 和 `owner_user`，分别精确对应 `creator_account_id` 和 `creator_user_id`。聊天可见、同一机器或同一项目都不等于归属已确认；不要用账号昵称、邮箱或从任意文件猜测值。这个模式每次只检查第一条元数据，两个标识都完全匹配才会进一步读取正文；正文读取也重新检查，不会依赖上次名单直接读取。
3. 用无真实信息的合成聊天验证后，再按用户授权范围首次补档。**含账号标识的配置与清单留本机，不提交仓库。** 不确定归属、内部工作会话或不应进入归档的聊天不要启用自动模式。

## 识别范围与增量

- 当前识别命名为 `rollout-日期T时间-UUID.jsonl` 的本机 Codex JSONL 记录。首条 `session_meta` 的 UUID 必须与文件名一致，来源须是支持的人工会话类型并具备创建账号和用户字段。已验证账号模式只接纳同时匹配两个指定标识的会话；这不是验签，不适用于其他人可写或来源不可信的记录目录。
- 只取 `response_item` 中可见的文本提问和回复；忽略工具输出、推理、系统包装、代理任务等，不提取截图或附件。含非文本、内置指令包装的轮次不传给后续整理。一个被省略的问题不会把自己的回复归到前一个问题。内部结构不是公开稳定导出格式，Codex 版本变化应重新验证。
- 来源修改日期取本机文件 mtime 并转换为 UTC；归档移动不会换会话 ID。同步核心记录修改日期，以规范化正文指纹决定是否新增或更新，因此同一修改时间下的正文变化不会漏掉，仅移动记录或修改时间戳也不会重录。
- 消息锚点优先用源消息 ID，再用记录时间与同时间重复序号，最后才用同角色顺序号。最后一种仅对原位编辑和末尾追加较稳定，插删前文可能改变身份；出现不明确的分题变化应待复核，不能据此删除已有档案。
- 活动文件最近两分钟有变化、读取中变化、尾行不完整、重复副本、源身份不一致、旧格式、链接或超出容量限制时不读取或延后。两分钟静置不是线程完成证明；没有完整回复的最后一轮也不会立刻纳入。调用端应把未返回的获批 ID 记为无法读取或待重试，而不是记为已入库。仅在云端、异机或已经删除的聊天不会由此恢复。

需要兼容不同存储版本时，先核对 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)，或者用官方、经授权的来源导出并转成通用输入格式；不通过浏览器登录态或绕过权限抓取聊天。
